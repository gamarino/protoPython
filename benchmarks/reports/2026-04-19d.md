**Notes:**
- **First Release-mode benchmark** — Step 3 and earlier used an incompatible build dir (different
  protoCore API). This is the first apples-to-apples comparison using the correct `build-release/`
  directory configured with `-DCMAKE_BUILD_TYPE=Release`.
- `startup_empty` (1.05x) and `int_sum_loop` (1.06x): essentially at parity with CPython.
  The startup overhead was dominated by name-resolution cost now eliminated.
- `call_recursion` (fib(25)): **no longer times out** — completes in 38.48s (910x). The recursive
  self-call inside `fib` now uses `LOAD_GLOBAL` → `env->resolve()` ptrCache (O(1)) instead of
  `LOAD_NAME` which traversed the per-frame attribute chain (O(depth) + always missed). Per-call
  overhead: ~158µs vs ~346µs pre-Step4 (measured on debug binary).
- `list_append_loop` / `str_concat_loop` / `range_iterate`: 9–13x vs 36–65x prior. These tight
  loops call functions repeatedly; the gains come from: (a) eliminating parameterNames/localNames
  ProtoList construction (4-6 fewer allocs per call), (b) LOAD_GLOBAL skipping 2 frame attribute
  lookups, (c) isFunctionScope_ emitting LOAD_GLOBAL for free variables (e.g., `range`, `N`).
- `multithread_cpu`: 53.64x vs 82.89x prior — function call improvements also reduce per-thread
  lock contention (fewer allocations → fewer GC polls).
- `attr_lookup`: 52.77x vs 89.73x — the 100k-iteration loop benefits from LOAD_GLOBAL direct
  resolve for `FastObject` and `range` lookups at the call site.
- **Geomean: 35.76x → 24.06x: 33% additional improvement.** Cumulative from V92 baseline: 56.4x → 24.06x (~57% total).

**Changes (Step 4: function call fast-path):**

1. **bindVar debug guard** (`ExecutionEngine.cpp`): Moved `toUTF8String` inside `PROTO_ENV_DIAG`
   guard. Previously called unconditionally for every parameter on every function call.

2. **Eliminate parameterNames/localNames construction** (`ExecutionEngine.cpp`):
   `runUserFunctionCall` was building two ProtoLists from `co_varnames` then passing them to
   `ContextScope` with `args=nullptr`. Since the ProtoContext constructor early-exits when
   `parameterNames=nullptr`, these lists were 4-6 wasted allocations per call. Now passes
   `nullptr, nullptr` for both; `automatic_count` alone drives slot allocation.

3. **LOAD_GLOBAL skips frame chain** (`ExecutionEngine.cpp`): Removed the `frame->getAttribute`
   + `__data__` sparse-list check from `OP_LOAD_GLOBAL`. Global variables are never stored in
   the local frame; the check always missed. Now goes directly to `env->resolve()` which uses a
   `thread_local` ptrCache for O(1) lookup after the first call per name.

4. **isFunctionScope_ compiler flag** (`Compiler.h`, `Compiler.cpp`): Added `isFunctionScope_`
   flag set on body compilers for all function defs, async defs, lambdas, and comprehensions.
   In `emitNameOp`, when a name is not in `localSlotMap_`, `nonlocalNames_`, or `globalNames_`,
   the fallthrough now emits `LOAD_GLOBAL` (not `LOAD_NAME`) in function scope. This avoids the
   `LOAD_NAME` path which checked own-attrs (miss), traversed the prototype chain (miss), then
   called `env->resolve()` — same final result but with 2 extra lookups. Functionally identical:
   free variables in function scope are always globals/builtins.
