## V97 Notes

### Fix: Replace uncached `std::getenv("PROTO_ENV_DIAG")` with cached `get_env_diag()`

**Root cause found**: The hot bytecode dispatch loop in `ExecutionEngine.cpp` (line 2237 of the
prior commit) called `std::getenv("PROTO_ENV_DIAG")` on **every single bytecode executed** —
`getenv()` is a glibc call that must search the process environment table on every invocation.
For fib(26) × 10 iterations this amounts to ~26.7M `getenv()` calls in `executeBytecodeRange`
alone, plus ~79 additional call-sites in `PythonEnvironment.cpp` (attribute lookups, module
imports) and further call-sites in `BuiltinsModule.cpp`, `Compiler.cpp`, and other modules.

`PythonEnvironment.cpp` is the deepest call-site: it is invoked on every attribute access,
which is why `attr_lookup` improved the most (−59%).

**Fix implemented**:

1. **New header** `include/protoPython/DiagUtils.h`:
   ```cpp
   inline bool diagEnabled() {
       static const bool val = (std::getenv("PROTO_ENV_DIAG") != nullptr);
       return val;
   }
   inline bool get_env_diag() { return protoPython::diagEnabled(); }
   ```
   The `static const bool` is initialized once at first call and cached for the process lifetime.

2. **Files updated** (all `std::getenv("PROTO_ENV_DIAG")` → `get_env_diag()`):
   - `src/library/ExecutionEngine.cpp`: 47 replacements; removed old local `get_env_diag()`
     function (lines 88–94 of prior version); fixed `const char* diag_env` → `bool diag_env`
   - `src/library/PythonEnvironment.cpp`: 79 replacements; removed broken local recursive
     `get_env_diag()` stub; fixed `bool diagnostics = get_env_diag() != nullptr` → `get_env_diag()`
   - `src/library/BuiltinsModule.cpp`: 62 replacements
   - `src/library/Compiler.cpp`: 10 replacements
   - `src/library/OsModule.cpp`: 4 replacements
   - `src/library/CollectionsAbcModule.cpp`: 1 replacement; fixed `!= nullptr` type mismatch
   - `src/library/ExceptionsModule.cpp`: 3 replacements
   - `src/library/Tokenizer.cpp`: 1 replacement

### Analysis

`attr_lookup` improved 59% because `PythonEnvironment::getAttribute` is called on every
attribute read and contained ~79 `std::getenv` calls. Each attribute lookup now avoids all of
those, replacing them with a single cache read.

`call_recursion` improved 4.6% (−130ms) because `executeBytecodeRange` dispatched one
`std::getenv` per opcode on every iteration through the bytecode loop (line 2237). For
fib(25)/242K recursive calls this is a significant cumulative cost at the bytecode level.

The remaining 47× slowdown on `call_recursion` relative to CPython is now not attributable
to the diagnostic check. True profiling (`perf record` with hardware counters) is required
to identify the dominant remaining cost. The system's `perf_event_paranoid=4` setting
currently blocks profiling; run `sudo sysctl -w kernel.perf_event_paranoid=1` to enable.
