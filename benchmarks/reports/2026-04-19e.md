**Notes:**

- **Bytecode native cache** (`executeBytecodeRange`): The dominant improvement. The bytecode
  `ProtoTuple` is now converted to a flat `std::vector<int>` at the top of every
  `executeBytecodeRange` call. Each instruction dispatch then does two `bc[i]`/`bc[i+1]` native
  array reads instead of two `bytecode->getAt(ctx, i)` AVL-tree lookups. For a ProtoTuple of
  n elements, `getAt` costs O(log n) comparisons. For n ≈ 16 (typical function), this is ~4
  comparisons per fetch → 8 comparisons per instruction pair → ~64 comparisons/function call.
  Native array: 2 reads. Savings: ~97% of bytecode fetch cost.

  Impact is broad because **every** `executeBytecodeRange` call benefits — module startup, imports,
  function calls, comprehensions. The 24-29% absolute improvement for startup/int_sum/list_append/
  attr_lookup all stem from this change.

- **Skip `f_back` and `f_locals` for CO_OPTIMIZED functions** (`runUserFunctionCall`): CO_OPTIMIZED
  functions bind parameters into automatic-locals slots (not frame attributes). The `f_back`
  (traceback chain) and `f_locals` (for `locals()/sys._getframe()`) attributes are only needed for
  debugging and introspection — not normal execution. Skipping them for CO_OPTIMIZED functions saves
  2 `setAttribute` calls per function invocation (each creates a new immutable AVL node). For
  fib(25) with ~150k recursive calls: ~300k fewer AVL allocations (~1.2M fewer cells).

  Impact: call_recursion -6.2% absolute, memory_pressure -7.3%.

- **call_recursion** (fib(25)): 38480ms → 36097ms = 6.2% absolute improvement. Still 865x slower
  than CPython (session-dependent; across sessions this ranged 690–920x). The remaining overhead is
  dominated by per-call `ProtoContext` allocation and the frame construction cost (4 immutable AVL
  ops: newObject + addParent(frameProto) + setAttribute(f_code) + setAttribute(f_globals)).

- **startup_empty / int_sum_loop**: 47ms → 35ms / 50ms → 36ms. These are now essentially at CPython
  parity for simple workloads (1.17–1.24x), down from 1.05–1.06x in Step 4 on a loaded machine.
  Under comparable load conditions these should remain near 1.0x.

**Changes (Step 5: bytecode native cache + CO_OPTIMIZED frame slimming):**

1. **Bytecode native cache** (`ExecutionEngine.cpp:executeBytecodeRange`): Added a `std::vector<int>
   bc` that is populated once at function entry by iterating over the bytecode ProtoTuple. The main
   dispatch loop replaces `bytecode->getAt(ctx, i)` calls with `bc[i]` native reads. The upfront
   cost (n AVL lookups) is fully amortized for any code path that executes more than one instruction.

2. **Skip `f_back` for CO_OPTIMIZED** (`ExecutionEngine.cpp:runUserFunctionCall`): Added
   `if (!(co_flags & CO_OPTIMIZED))` guard around the `setAttribute(f_back, parentFrame)` call.
   CO_OPTIMIZED functions do not need the traceback frame chain during normal execution.

3. **Skip `f_locals` for CO_OPTIMIZED** (`ExecutionEngine.cpp:runUserFunctionCall`): Added
   `if (!(co_flags & CO_OPTIMIZED))` guard around the `setAttribute(f_locals, frame)` self-reference
   that enables `locals()`. CO_OPTIMIZED functions store parameters in slots, not frame attributes,
   so `locals()` would need slot reconstruction anyway (that path is handled separately when called).
