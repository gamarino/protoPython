# SP1 — Test Infrastructure Audit & Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Identify and repair every protoPython gap that prevents the CPython test-infrastructure modules — `test.support`, `doctest`, `inspect`, `annotationlib`, `unittest` — from working correctly enough to run the Essential category of `Lib/test/`.

**Architecture:** Three phases — (1) write five synthetic API-surface probes that emit JSON gap lists, (2) Z-filter the gaps into a prioritized backlog, (3) TDD per gap with one commit per backlog entry. Stop condition: 4 weeks elapsed in Phase 3 OR 20 Phase-3 commits, whichever first.

**Tech Stack:** protoPython (C++ interpreter + Python stdlib in `lib/python3.14/`); probes are pure Python; fixes land in `protoPython/src/` (C++) or `protoPython/lib/python3.14/` (Python) per root-cause classification.

## Phase 1 — Audit

### Task 1.0: Shared probe library

**Files:**
- Create: `tests/audits/_probe_lib.py`

**Plan v2 note (2026-04-29):** During execution of v1 we discovered three protopy bugs that the audit infrastructure cannot avoid: (1) `json.dumps(int)` returns garbage instead of the integer; (2) `sys.path.insert` updates `sys.path` but does not affect import resolution; (3) importing a local module emits ~240 lines of `DEBUG:` output to **stdout**, not stderr. The library now emits **JSONL** (one entry per line) using string-only `json.dumps` calls (every value stringified first), all probes are run with `cwd=tests/audits/` so local imports work via the existing `.` entry on `sys.path`, and probe-to-file redirections filter `^DEBUG:` lines. These three protopy bugs are filed in the SP1 archived list (Task 2.3) for follow-up.

- [ ] **Step 1.0.1: Create the shared library**

```python
# tests/audits/_probe_lib.py
"""Shared helpers for SP1 audit probes.

Each probe imports `expect`, calls it many times, then emits the
collected gaps as JSONL on stdout via `emit()`.

The output format is JSONL (one JSON object per line):
- Line 1 is a header: {"module": "...", "format": "jsonl-strings",
                       "total": "N", "passes": "K", "fails": "M"}.
- Each subsequent line is one entry as a JSON dict where ALL VALUES
  ARE STRINGS.  This works around protopy bug #1: `json.dumps(int)`
  returns "<NoneType object at (nil)>".  We stringify every value
  manually, then pass through json.dumps which works correctly for
  strings.  Triage code (python3, not protopy) reads back and treats
  values as strings throughout; integer fields are interpreted at
  read time if needed.
"""
import json
import traceback

_gaps = []


def expect(name, fn, validate=None):
    """Run fn(); record success/failure with full context.

    Args:
        name: stable identifier for the gap (e.g. "doctest.testmod_basic").
        fn: zero-arg callable that exercises the API.
        validate: optional callable(result) -> bool; if provided and returns
            False, the entry is recorded as FAIL with reason "validate".
    """
    try:
        result = fn()
    except Exception as e:
        _gaps.append({
            "id": name,
            "status": "FAIL",
            "exc_type": type(e).__name__,
            "exc_msg": str(e),
            "traceback": traceback.format_exc(),
        })
        return
    if validate is not None:
        try:
            ok = validate(result)
        except Exception as e:
            _gaps.append({
                "id": name,
                "status": "FAIL",
                "exc_type": "ValidateError",
                "exc_msg": "validate raised %s: %s" % (type(e).__name__, e),
                "traceback": traceback.format_exc(),
            })
            return
        if not ok:
            _gaps.append({
                "id": name,
                "status": "FAIL",
                "exc_type": "ValidateMismatch",
                "exc_msg": "result did not satisfy validator: %r" % (result,),
                "traceback": "",
            })
            return
    _gaps.append({
        "id": name,
        "status": "PASS",
        "result": repr(result)[:200],
    })


def _serialize_entry(entry):
    """Build a single-line JSON object from a dict.

    All values are converted to strings via str() before being passed
    to json.dumps — this avoids protopy bug #1 (json.dumps of int).
    Result is a flat JSON object with string-only values.
    """
    parts = []
    for k, v in entry.items():
        parts.append(json.dumps(str(k)) + ":" + json.dumps(str(v)))
    return "{" + ",".join(parts) + "}"


def emit(module_name):
    """Print collected gaps as JSONL on stdout (one entry per line)."""
    passes = sum(1 for g in _gaps if g["status"] == "PASS")
    fails = sum(1 for g in _gaps if g["status"] == "FAIL")
    header = {
        "module": module_name,
        "format": "jsonl-strings",
        "total": str(len(_gaps)),
        "passes": str(passes),
        "fails": str(fails),
    }
    print(_serialize_entry(header))
    for g in _gaps:
        print(_serialize_entry(g))
```

and any other Essential test that runs doctests.

def _testmod_empty():
    import doctest, types
    m = types.ModuleType("empty")
    return doctest.testmod(m)
expect("doctest.testmod_empty", _testmod_empty,
       validate=lambda r: r.attempted == 0 and r.failed == 0)

# 3. testmod with passing doctest
def _testmod_pass():
    import doctest, types
    src = '''
def f():
    """
    >>> f()
    42
    """
    return 42
'''

    exec(compile(src, "<dt_pass>", "exec"), m.__dict__)
    return doctest.testmod(m, verbose=False)

def g():

    99

# tests/audits/probe_inspect.py
"""Audit probe for inspect — exercises the introspection API used by
unittest, doctest, and Essential tests."""
# Run from tests/audits/ so the local _probe_lib import resolves via
# the existing "." entry on sys.path.  protopy bug #2 makes
# sys.path.insert ineffective, so we rely on cwd.
from _probe_lib import expect, emit

import inspect

# 1. signature on plain function
def _sig_plain():
    def f(a, b, c=1): pass
    return inspect.signature(f)
expect("inspect.signature_plain", _sig_plain,
       validate=lambda s: list(s.parameters) == ["a", "b", "c"])

# 2. signature with kw-only
def _sig_kwonly():
    def f(a, *, b): pass
    return inspect.signature(f)
expect("inspect.signature_kwonly", _sig_kwonly,
       validate=lambda s: s.parameters["b"].kind == inspect.Parameter.KEYWORD_ONLY)

# 3. signature with varargs / varkwargs
def _sig_varargs():
    def f(*args, **kwargs): pass
    return inspect.signature(f)
expect("inspect.signature_varargs", _sig_varargs,
       validate=lambda s: any(p.kind == inspect.Parameter.VAR_POSITIONAL
                              for p in s.parameters.values()))

# 4. signature on bound method
def _sig_bound():
    class C:
        def m(self, x): pass
    return inspect.signature(C().m)
expect("inspect.signature_bound_method", _sig_bound,
       validate=lambda s: list(s.parameters) == ["x"])

# 5. BoundArguments
def _bound_args():
    def f(a, b=2): pass
    s = inspect.signature(f)
    ba = s.bind(1)
    ba.apply_defaults()
    return dict(ba.arguments)

       validate=lambda r: r == {"a": 1, "b": 2})

- [ ] **Step 3.0.4: Identify root cause**

For the example Gap `SP1-G023`:

1. The traceback in the audit JSON pointed to `lib/python3.14/doctest.py:OutputChecker.check_output`.
2. Read the relevant function:

3. Trace the path in the function the reproducer hits. Most often the bug is one of:
